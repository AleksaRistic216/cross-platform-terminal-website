## 2. Ask HN: How do you use multiple sessions for software engineering?

- https://news.ycombinator.com/item?id=49479775 — opened 2026-08-28, 2 comments
- **Post today or skip it.** HN closes threads to comments after about 14 days, and this one hits
  that today.
- **Why:** the asker wants a routine, not a tool. This reply deliberately doesn't mention CPT. The
  playbook allows one CPT mention per five helpful comments, and this is one of the five.

```
I build CPT, so take this with salt — though nothing below needs it.

What made it work for me:

1. One task per session, each in its own git worktree, so two agents never edit the
   same checkout.
2. Stop polling. Claude Code's Notification hook fires when it's waiting on a permission
   prompt or sitting idle; point it at notify-send or a desktop toast and you only look at
   a session when it asks. The hooks guide has the snippet.
3. Write down what "done" looks like before starting the session. jdw64 is right above:
   that's what makes the result converge, far more than agents reviewing each other.
```
